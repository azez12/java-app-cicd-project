# Java Spring Boot CI/CD with Jenkins and Docker

A simple **Java Spring Boot application** demonstrating a complete **CI/CD pipeline** using **Jenkins, Maven, Docker, GitHub, and Docker Hub**.

The project automatically builds the Java application, creates a Docker image, pushes the image to Docker Hub, and deploys the application as a Docker container on an AWS EC2 server.

---

## 🚀 Project Overview

This project demonstrates the following DevOps workflow:

```text
Developer

    ↓
Spring Boot JAR
    ↓
Docker Build
    ↓
Docker Hub
    ↓

    ↓

```

The application is a simple Spring Boot REST API.

# 🐳 Dockerfile

The project uses Docker to package the Spring Boot application into a container.

```dockerfile
FROM eclipse-temurin:17-jre

WORKDIR /app

COPY target/demo-0.0.1-SNAPSHOT.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java","-jar","app.jar"]
```

## Dockerfile Explanation

### 1. Base Image

```dockerfile
FROM eclipse-temurin:17-jre
```

The container uses the Eclipse Temurin Java 17 JRE image.

We only need the **JRE** inside the container because Maven already compiles the application and creates the JAR.

The application is compiled in the Jenkins build stage, so the Docker container only needs Java to **run** the JAR.

---

### 2. Working Directory

```dockerfile
WORKDIR /app
```

Creates and switches to `/app` inside the container.

The application will be located in this directory.

---

### 3. Copy the JAR

```dockerfile
COPY target/demo-0.0.1-SNAPSHOT.jar app.jar
```

Copies the JAR generated by Maven:

```text
target/demo-0.0.1-SNAPSHOT.jar
```

into the Docker image as:

```text
/app/app.jar
```

---

### 4. Expose Port

```dockerfile
EXPOSE 8080
```

Documents that the Spring Boot application listens on port `8080` inside the container.

---

### 5. Start the Application

```dockerfile
ENTRYPOINT ["java","-jar","app.jar"]
```

This command starts the Spring Boot application when the container starts.

# 🔄 Jenkins CI/CD Pipeline

The project uses a **Declarative Jenkins Pipeline**.

The pipeline is stored in the repository as:

```text
Jenkinsfile
```

Jenkins gets the Jenkinsfile from GitHub using **Pipeline script from SCM**.

---

## Pipeline Stages

The pipeline contains the following stages:

```text
Checkout
   ↓
Check Java
   ↓
Build
   ↓
Docker Login
   ↓
Docker Build
   ↓
Docker Push
   ↓
Deploy Container
```

---

## 1. Checkout

```groovy
stage('Checkout') {
    steps {
        git branch: 'main',
            url: 'https://github.com/azez12/java-app-cicd-project.git'
    }
}
```

Jenkins clones the project from GitHub.

---

## 2. Check Java

```groovy
stage('Check Java') {
    steps {
        sh 'java -version'
        sh 'javac -version'
        sh 'mvn -version'
    }
}
```

This stage verifies that Jenkins has the required tools:

- Java
- Java Compiler (`javac`)
- Maven

The project currently uses:

```text
Java 21
Maven 3.9.0
```

---

## 3. Build

```groovy
stage('Build') {
    steps {
        sh 'mvn clean package'
    }
}
```

Maven:

1. Cleans the previous build.
2. Compiles the Java source code.
3. Runs tests.
4. Creates the JAR file.
5. Spring Boot repackages the JAR.

The generated artifact is:

```text
target/demo-0.0.1-SNAPSHOT.jar
```

The JAR is also archived by Jenkins.

# 🔐 Docker Login

Jenkins logs into Docker Hub using Jenkins Credentials.

```groovy
withCredentials([
    usernamePassword(
        credentialsId: 'dockerhub',
        usernameVariable: 'DOCKER_USERNAME',
        passwordVariable: 'DOCKER_PASSWORD'
    )
]) {
    sh '''
        echo "$DOCKER_PASSWORD" | docker login \
        -u "$DOCKER_USERNAME" \
        --password-stdin
    '''
}
```

The Docker Hub credentials are stored securely in Jenkins Credentials rather than being hardcoded in the Jenkinsfile.

# 🏗️ Docker Build

Jenkins builds the Docker image:

```bash
docker build -t ${IMAGE_NAME}:${BUILD_NUMBER} .
```

The image name is:

```text
abdelaziz225/devops-java-app
```

The Jenkins build number is used as the Docker image tag.

For example:

```text
Build #11 → abdelaziz225/devops-java-app:11
Build #12 → abdelaziz225/devops-java-app:12
Build #13 → abdelaziz225/devops-java-app:13
```

This gives every build a unique image version.

---

# 📤 Docker Push

After building the image, Jenkins pushes it to Docker Hub:

```bash
docker push ${IMAGE_NAME}:${BUILD_NUMBER}
```

Example:

```text
abdelaziz225/devops-java-app:12
```

The image can then be pulled from Docker Hub by the deployment server.

---

# 🚀 Deploy Container

The deployment stage first removes the previous container:

```bash
docker stop java-app || true
docker rm java-app || true
```

Then it pulls the new image:

```bash
docker pull ${IMAGE_NAME}:${BUILD_NUMBER}
```

Finally, it starts the new container:

```bash
docker run -d \
    --name java-app \
    -p 8081:8080 \
    ${IMAGE_NAME}:${BUILD_NUMBER}
```

## 🔌 Port Mapping

The application listens on:

```text
8080
```

inside the Docker container.

However, Jenkins itself is running on port `8080` on the EC2 host.

Therefore, the container is exposed using:

```text
8081:8080
```

This means:

```text
EC2 Host Port     Container Port
     8081    →        8080
```

So the application can be accessed through:

```text
http://EC2-PUBLIC-IP:8081
```


Port `8080` is used by Jenkins, while port `8081` is mapped to the Spring Boot container.
